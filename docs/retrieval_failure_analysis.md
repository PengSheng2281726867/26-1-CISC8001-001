# ALT 检索失败分析：已测证据与待验证原因

本次仅分析已保存的 ALT-30/100、预留示范和既有轨迹。未训练新模型、未启动新仿真、未改变原实验参数或结果。两组原始运行记录保持不变。

复现离线诊断：

```powershell
& 'D:\Code\Course_code\DP\.conda\pusht\python.exe' -B scripts/diagnose_representation.py
```

原分析 ID 已存在时会拒绝覆盖；重复运行需复制诊断 JSON 并选择新的 analysis_id，再通过 `--config` 指定。设置在 configs/diagnostics/retrieval_failure_v1.json；结果在 results/diagnostics/retrieval_failure_v1.json；图在同名 PNG。诊断与模型文件均有校验值。两组模型使用相同20条预留示范的全部2426帧，模型输入仍只有当前图像和推杆 x,y。

## 1. 数值位置分支的作用确实很弱

选取256个均匀分布的预留帧，固定图像，只将数值位置替换成另一帧的位置。替换前后位置平均相差181.55个世界坐标单位。

| 诊断 | ALT-30 | ALT-100 |
|---|---:|---:|
| 仅替换 x,y 后，top1 改变比例 | 1.56% | 2.73% |
| 仅替换图像后，top1 改变比例 | 100% | 100% |
| 仅替换 x,y 后，平均嵌入余弦变化 1-cos | 0.000398 | 0.000075 |
| 融合首层图像贡献的中心化 RMS | 10.55 | 19.91 |
| 融合首层位置贡献的中心化 RMS | 0.233 | 0.208 |

代码确实拼接了两个分支，但其数值变化量失衡，融合检索明显由图像主导。这支持“数值位置约束太弱”的判断。替换图像/位置会产生不一致的人工输入，这只是函数敏感性探针，并非物理有效状态或新策略。图像中也能看到推杆，因此不能据此断言模型完全不使用任何位置信息。

## 2. 状态匹配误差真实存在

以下均为预留帧与匹配示范帧的平均误差。位置单位属于512×512模拟世界，不是96×96图像像素；角度采用周期差，范围0至180度。

| 指标 | ALT-30 | ALT-100 |
|---|---:|---:|
| 推杆位置 L2 误差 | 39.85 | 59.66 |
| T 块位置 L2 误差 | 46.42 | 44.49 |
| T 块角度误差（度） | 38.31 | 37.97 |
| 8步绝对动作块 RMSE | 50.03 | 52.90 |
| 匹配余弦均值 | 0.8727 | 0.9556 |

角度误差中位数为8.21/6.94度，但95分位达到162.52/156.06度：存在严重的尾部错误，而不是所有匹配都失败。余弦分数没有被校准成几何准确率，跨模型更不能当成概率比较。动作 RMSE 只是与该预留示范专家动作的差异；不同动作都可能有效，因此它不是动作正确率。

诊断还用完整状态构造了一个明确标注的几何参考：最小化 `(推杆距离/512)^2 + (T块距离/512)^2 + (角度差/pi)^2`。它只用于分析，不向 ALT 提供额外输入，也没有执行任何参考策略。

| 几何参考的平均误差 | ALT-30 的同一库 | ALT-100 的同一库 |
|---|---:|---:|
| 推杆位置 | 22.96 | 15.68 |
| T 块位置 | 29.17 | 22.30 |
| T 块角度（度） | 8.31 | 4.99 |

这说明库中存在几何上更适合的候选，当前视觉嵌入没有稳定选中它们。该参考依赖特权状态和人为指定的几何权重，不是真实正确匹配标签，也不是闭环性能上界；不能据此声称图像策略必然可以达到某个分数。仅匹配推杆位置虽然能降低推杆误差，却会让 T 块误差变大，说明只强化 x,y 也不足以解决整个任务。

## 3. 训练目标与动作检索需求有差距

当前 NT-Xent 只把同一帧的两个颜色增强视图拉近，并把其他帧作为负样本；没有动作、接触关系、T 块姿态或任务进度约束。该目标并不保证相近嵌入对应可互换的专家动作。两个分支也没有在拼接前各自归一化，测得的贡献量失衡值得优先检查。

这是机制上合理、与测量一致的解释，但本次没有重训或消融，尚未证明某个具体损失/归一化修改能提高闭环表现。也没有发现所有嵌入都坍缩成一个向量：随机不同库条目的平均余弦约0.0076/0.0050，中心化协方差有效秩约72/68。局部错误相似依然明显。

## 4. 绝对动作回放会放大错误匹配，并形成循环

策略直接使用匹配示范中的绝对目标坐标，正常每8个动作才重新观察一次（控制10Hz，约0.8秒）。当前推杆或 T 块状态不同，示范中有效的接近/接触动作可能在当前状态无效；随后再次取到同一块，便可能停滞。

既有完整轨迹中，ALT-30/100 分别有362/369次相邻查询同时出现“同一匹配且推杆位置不变”；另有158/146次交替两状态的返回转移。这些是转移计数，不是失败回合数或独立事件数。预定义视频已经显示相应的停滞/循环。

仅单帧输入看不到运动历史；环境控制还依赖推杆速度。这也可能影响动作复用，但贡献大小尚未经消融确认。8步长度、单帧、top1、无补偿/无回退均为冻结基线，未在本次分析中调整。

## 判断与下一步优先级

目前证据最强的链条是：数值位置约束弱，视觉嵌入没有可靠保留任务所需的精确几何，直接回放绝对动作后产生偏差和循环。现有索引、时间对齐、图像预处理、动作单位与官方接口检查没有发现异常；这不等于已经排除所有实现问题。

后续最值得单独验证的是分支尺度/位置约束，以及嵌入是否应体现接触几何或动作相容性。只有这些离线匹配诊断改善后，再检查动作块时长的独立影响；不可把多个改动一起加入原基线。所有建议都尚未实施，训练与新增闭环实验继续保持暂停。

另用独立 NumPy FP64 计算复核全部14556行派生指标，检查了示范划分、模型/库/数据/脚本校验值。结果在 results/diagnostics/retrieval_failure_v1_verification.json。FP32距离计算与独立重算的最大差为0.141个世界坐标单位，不影响上述量级判断。完整逐帧表留在忽略的 artifacts/diagnostics/ 下，Git保存汇总、图、配置及文件校验值。
